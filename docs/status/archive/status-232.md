## 概要

**Hermite OFF は frac=0.84 で max_increments=15000 に到達し打ち切り**、
**Hermite ON は frac=0.08 で事実上スタック**。

## Hermite ON が n_periods=30 で壊滅する原因

### 1. Node tangent がメッシュ全体に依存

`_compute_node_tangents()`（`_compute.py:297-327`）は各ノードの接線を隣接要素方向の平均で計算。
n_periods=30 で変形が大きくなると、NR 反復のたびに接線ベクトルが急変し、Hermite 曲線形状がステップごとに揺れる。

### 2. ギャップ計算のジャンプ → active 判定崩壊

Hermite 曲線上の最近接点 (s,t) を Newton 法で求める際、接線急変により s,t がジャンプ → gap が不連続に変化 → active 判定が外れる → **22 点 → 6 点に激減**。

### 3. 形状関数係数の乖離

Hermite 形状関数の微分 dc_ds は s=0.5 で線形の 1.5 倍の勾配。K_st（接触点滑り剛性）を過大評価し NR 収束を悪化させる。摩擦アセンブリが線形のままという矛盾も残存。

## 判断

### Hermite 改善は後回し

- n_periods=30 では Hermite OFF でもまだ frac=1.0 に到達していない
- Hermite ON の問題（接線感度、gap ジャンプ）は構造的で、修正工数が大きい
- **先に dt を大きく保つ対策に集中すべき**

### 次の課題（roadmap に追加済み）

1. **freeze_geometry_in_nr=True の必須化**: NR 内 s,t 凍結でカットバック削減
2. **Node tangent 計算の局所化**: 全体メッシュ依存を排除
3. **曲面連続関数化の代替手法調査**: B-spline/NURBS/IGA-C 等、Hermite 以外の C1 連続手法
4. **dt を大きく保つ対策**: adaptive timestepping の dt 下限引き上げ、接触チャタリング抑制、dt 回復ロジック改善
