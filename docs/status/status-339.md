## 概要

status-338 で確立した 7本撚線 κ_cr 実測手順を 19本撚線（1+6+12 構造）へ
スケールアップした。

**結論**: frac=1.0 完走には至らず **frac=0.4839 で収束失敗**（Type D stall、
status-319 で既知）。ただし **57 ペアの κ_cr データ取得に成功** しており、
分布統計・内層/外層の層間差を解析可能な部分成果を得た。

STA2 防止ルールに従い、数値を捏造せず「収束しなかった」と明記する。

## 7本撚線 vs 19本撚線 比較

| 観測量 | 7本 (status-338) | 19本 (frac=0.484) | 変化 |
|--------|------------------|-------------------|------|
| 接触活性化開始 frac | ~0.23 | ~0.10 | **早期化** |
| n_unique_pairs | 26 | 59 | 2.3x |
| max active | 15 | 41 | 2.7x |
| κ_cr mean | 5.80e-3 | 4.50e-3 | **22% 低下** |
| κ_cr CV | 0.30 | 0.33 | ほぼ同等 |

### 物理的解釈（暫定）
- **mean κ_cr 低下**: 19本ではより短い曲率で接触が成立（外層-外層や内層-外層の
  早期接触）。曲率スケーリングが n_strands 依存であることを示唆
- **CV 同等性**: 0.30〜0.33 は分布のばらつきが scale invariant であることを示唆、
  Papailiou の単一 κ_cr 仮定の修正は 30% 広がりで一般化可能
- **バイモーダル**: 内層対と外層対で接触力・梃子比が異なるため κ_cr が分岐する
  仮説 — 完走後にペアインデックスで層分類して検証すべき

## Type D stall 問題（status-319 既知）

- `Incr 270 (frac=0.4839)` で `D.stall+E:14(44%)` が支配
- FD 診断で K_c 不整合（全体系 `K@du` 相対誤差 1.0006、|FD-解析|/max=1.02）
- 原因は status-319 で解析済み: n=19 以降、低曲率で `ContactForceStStiffness`/
  `FrictionStStiffness` が n²（α≈2.07/2.04）スケール、アセンブリ誤差蓄積が
  stall を誘発
- 本 status では未対策のため frac=0.4839 で停止

## 次セッション向け Type D 対策ガイド（19本撚線 frac=1.0 完走への道）

### 観測された Type D stall の特徴（本実測ログより）
1. **低残差チャタリング**: `R_c=3.71e-05, R_s=2.51e-06` と小さいが収束せず
2. **rate=0.97〜1.0** で線形収束率が張り付く（Newton 方向不良の典型）
3. **接触凍結モード発動**（att=15, cycle=1/5）しても rate=2.23 まで跳ね返り
4. **active/sliding が固定**（active=41, sliding=326、状態変化なし）
   → 活性集合振動ではなく **接線剛性 K_c 自体が不正確**
5. **f_c 単独 FD 相対誤差 1.23**（7本の 1.75 より改善だが依然 K_c 不正確）

### 根本原因の仮説（優先度付き）

**仮説 A（最有力）: K_st の z 方向（comp=2）不整合が n² で悪化**
- status-289 で同定した `K_c 幾何項の comp=2 不整合` が 19本で顕在化
- 本実測で `comp別不整合: x=73%, y=22%, z=65%` → z 成分主因が再現
- 対策: `StJacobian.compute()` の z 方向カップリング項を再精査、特に
  Hermite 隣接ノード拡張（status-272）が層を跨ぐペアで誤差を蓄積している可能性

**仮説 B: gap_cull_threshold が n=19 で過緊縮**
- status-324 で導入した Huber 遷移幅ベースの自動 gap 閾値は n=7 想定
- 19本では**接触候補密度が 2.3x** のため閾値不適切の可能性
- 対策: `ContactForceStStiffnessInput.gap_cull_threshold` を n_strands 依存に
  スケーリング、または手動でキャリブレーション掃引

**仮説 C: 曲率プロファイル過粗さ**
- `n_increments_per_cycle=20` は 7本で完走可能だが 19本では粗すぎる
- 1 増分あたりの活性集合変化が大きく、Newton 修正が追従不能
- 対策: `n_increments_per_cycle=40` 復元（status-298 ベースライン）、
  または `adaptive_timestepping=True` でさらに細分化

**仮説 D: 接触凍結パラメータの n 依存性**
- status-284 の凍結モードは 7本でチューニングされている
- 19本では `cycle=2` で再凍結→解除→再凍結の往復が起きて停滞
- 対策: `chatter_detect_threshold` / `freeze_relax_factor` の再最適化

### 次セッション推奨アクション（優先順）

1. **K_c FD 診断ダンプ取得**（まず原因切り分け）
   ```python
   # StrandBendingOscillationConfig に追加
   enable_tangent_fd_diagnostic=True,
   tangent_fd_diagnostic_interval=50,  # 50増分毎
   ```
   目的: comp別不整合の n 依存性を 7本 vs 19本で比較、z 成分主因を確認

2. **n_increments_per_cycle=40 リトライ**（最も低コストな改善）
   - 所要時間見積もり: 534s → ~1200s（2x + 粗さ緩和効果）
   - 効果予測: Type D stall が解消すれば frac=0.484→1.0 完走
   - リスク: 低い。status-298 の 7本ベースラインと同値に戻すだけ

3. **gap_cull_threshold 手動掃引**（n=19 専用チューニング）
   - `ContactForceStStiffness` per-call 時間を犠牲にして安定性優先
   - 0.5x / 1.0x / 2.0x / 4.0x の 4点で frac 進行率を比較

4. **凍結モード OFF トライ**（仮説 D 検証）
   - `chatter_freeze_enabled=False` で通常 NR のみ、拡張 NR 上限 300 で力押し
   - frac=0.484 の停止点付近でのみの挙動観測

5. **仮説 A 着手**（根本対策、最大工数）
   - `_st_jacobian.py` の comp=2 カップリング項を全面見直し
   - 別セッションでの大きな工事（status-291〜296 と同規模）

## 開発運用メモ

- frac=1.0 完走未達の部分成果でも、**57 ペアの κ_cr データは有効**（物理的に
  スリップ遷移を通過したペアのみを記録する仕様のため、未到達の高 κ_cr ペア
  を欠落させるだけで、記録済みは正確）
- 完走未達だからといって 19本撚線 κ_cr の mean/CV 推定を捨てる必要はない。
  ただし**分布の右裾（高 κ_cr 側）は frac=1.0 完走データでしか観測できない**
  点は留意が必要
- STA2 ルール: 完走結果と混同しないよう、19本 mean=4.50e-3 は**「frac=0.484
  時点」の部分成果**として明記し、完走時の数値はまだ存在しないことを強調
